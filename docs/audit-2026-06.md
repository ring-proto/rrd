# rrd engineering audit — June 2026

A point-in-time engineering-quality and "build-on-top" audit of the `rrd` codebase,
focused on architecture, scalability, control/metrics surfaces, native orchestration,
and eBPF readiness. The RING algorithm itself is independently proven in `ring-sim`
and is **not** re-litigated here; this is about the engineering around it.

## Verdict

**Good foundation. Build on it.** The repo builds clean, is **clippy-clean (0 warnings)**,
has **~250 tests green (0 ignored)**, low smell counts (5 `panic!`, 1 `unsafe`, 0
`TODO/FIXME`), disciplined issue-tracked history, and well-documented invariants. The
architecture shows the right instincts: a single-owner **lock-free** engine, FIB
reconcile **off the hot loop**, a clean `Transport` trait, a real pure-model/executor
split in the lab, an **independent sim oracle**, and CNI crates with **zero compile-time
coupling**. The work ahead is "draw a few more seams + add the operability layer," not
a rescue. The gaps that exist line up with the project's stated priorities
(orchestration/automation/scaling/control/metrics) and are structural/capability gaps,
not quality defects.

| sim (`ring-sim`) | solid | Airtight determinism; best long-term regression/experiment asset. Wants a scenario/sweep driver + shared metrics module. |
| agent / cni (code) | solid | Clean, zero coupling — but the CNI direction is parked. |
| core engine (`ring-core`) | adequate | Great kernel; `step()` is a 190-line god-method; `RouterId(String)` identity costs per-step allocation and is FFI-unfriendly. |
| daemon runtime (`runtime.rs`) | adequate | Right concurrency model; `runtime.rs` is a mild god-file; control inputs are hardwired into the `select!`. |
| fib / data plane (`fib.rs`, `linkmon.rs`) | adequate | Solid single kernel-FIB backend; **no `DataPlane` trait → not eBPF-swappable yet**. |
| lab orchestration (`lab/*`) | adequate | Clean seam, but the live executor is an `unshare`/`nsenter`/`ip` shell-out fabric. |
| **control / metrics** | **needs-work** | **The weakest area** — no metrics export, unversioned/unauth protocol, rich engine introspection unexposed. |
| build / deps / CI | needs-work | (Being addressed) no CI, `Cargo.lock` gitignored, TUI compiled into the daemon, no release artifacts. |

## The five high-leverage seams

Most of the roadmap routes through a handful of moves, and the codebase already
demonstrates the pattern (`Transport`, `LabBackend`, single-owner engine), so these are
extensions, not rewrites. Each was independently flagged by multiple auditors.

1. **A shared `rrd-proto` crate** — versioned, typed request/response + error enums.
   The control JSON is currently hand-serialized in three places (daemon `control.rs`,
   `rrd-agent`, `rrd-cni`) with no version field. This is the contract every later
   surface (metrics, orchestration, policy) builds on.
2. **A `DataPlane` trait** mirroring `Transport`: `program(&[RouteIntent]) -> Stats`,
   `withdraw_all`, `installed_count`, `emergency_cleanup`. `FibReconciler` becomes one
   impl; an `EbpfDataPlane` another; a `Tee` gives kernel+eBPF "both" mode. `RouteIntent`
   is already a clean backend-neutral IR — just carry float weights and push the kernel
   `u8` ECMP quantization down into the FIB backend. This is the eBPF-option blocker, and
   it is a contained refactor.
3. **Native-netlink lab** — body-swap `RootlessBackend` to `rtnetlink` + `setns` behind
   the unchanged `LabBackend` trait (DryRun stays as a diff oracle). Removes the
   shell-out fabric, the `ip`-output string-scraping, the PID-placeholder netns, and the
   settle-sleeps. De-risked: `fib.rs`/`linkmon.rs` already prove the rtnetlink calls.
4. **Identity interning** (`RouterId` `String` → `Copy` handle) — removes per-step /
   per-tick `String` allocation and makes the engine FFI-friendly for an eventual C ABI.
5. **Decompose the god-method/file** — split engine `step()` into `relax`/`gc`/`reclaim`
   phases and `runtime.rs` into focused modules. Prerequisite for policy hooks, metrics
   taps, and per-phase benchmarking.

## Control / metrics — the priority gap

The owner's top priority is the weakest area. The `watch::Receiver<RibSnapshot>` is the
right backbone; build on it. Missing:

- No Prometheus/OpenMetrics export — observability is a 5-second log line + a one-shot
  socket query (`runtime.rs`, `control.rs`).
- Rich engine introspection exists but is unexposed: `peek_vit`/`peek_pot`/`peek_hops`,
  `charge`/`load`, `neighbor_count`, per-dest `route()` (`engine.rs:231-258`). No way to
  dump the RIB, neighbours, or per-dest `f`/`V` for debugging convergence under stress.
- Control protocol has no version, request-id, or typed error taxonomy; no streaming
  `subscribe`; no runtime knob changes (all engine tunables frozen at boot).
- Control sockets have no permissions hardening / `SO_PEERCRED` authz — an
  unauthenticated local route-injection surface.

## Scale cliffs to fix before "beating it up"

- Engine GC eviction + compaction is `O(ndest²)` via linear `evict.contains` scans
  (`engine.rs:432-440, 523-526`) — quadratic spike on a topology-wide withdrawal.
  Mask it to a single `O(ndest)` pass.
- Per-step `RouterId(String)` clones in delta emission / `desired_routes` / `compact`
  scale allocation with the dest table (seam #4 fixes this).
- Runtime per-tick full-set rebuild + canonical sort + whole-`Vec` `PartialEq` diff
  (`runtime.rs:473-490`) — move to a map-based per-prefix delta; reuse persistent
  scratch Vecs; `Arc` the snapshot payload.
- `in_use` neighbour-reclamation builds a fresh `HashSet` every step even when nothing
  is prune-eligible.

## Recommended sequence

- **Phase 0 — hygiene (in progress):** commit `Cargo.lock`; CI (fmt + clippy `-D
  warnings` + test `--locked`); `rust-toolchain.toml` + MSRV; `workspace.dependencies`;
  README/LICENSE. *(Later:* gate the TUI behind a feature / extract an `rrd-lab` crate;
  park `rrd-cni` + the k8s half of the agent; systemd unit + static/musl + container.)*
- **Phase 1 — control + metrics (top priority):** `rrd-proto`; a daemon-facing `rrdctl`
  (status / dump-rib / neighbors / add-origin / subscribe); expose engine introspection;
  OpenMetrics `/metrics` + `/healthz`/`/readyz`; `SO_PEERCRED` authz + socket perms.
- **Phase 2 — native-netlink orchestration:** seam #3 + one headless `LabHarness`
  ("spin up N daemons, run scenarios"); retire the duplicate bash harness as env-gated
  integration tests.
- **Phase 3 — swappable data plane + eBPF:** seam #2, then `EbpfDataPlane` + a
  `--dataplane kernel|ebpf|both` selector; replace the `Drop`-shells-out-to-`ip` backstop
  with a backend `emergency_cleanup`.
- **Phase 4 — scale hardening:** seams #4/#5 + the cliffs above.
- **Later (seams designed now):** a **policy engine** at the single `LocalOriginCommand`
  chokepoint / `desired_routes` policy seam (and finally wire the dead `weight_quantum`).

The full per-area findings (with severities and file:line) are retained from the audit
run that produced this summary.
